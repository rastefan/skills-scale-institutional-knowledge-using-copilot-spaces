# OctoAcme Project Management Docs

This README provides a central index to OctoAcme's project management process documents and a brief overview of the processes used to plan, deliver, and improve work.

OctoAcme follows a lightweight, iterative lifecycle that moves work from initiation through planning, execution, release, and retrospective. Projects begin with a one-pager that captures the problem statement, success metrics, stakeholders, timeline, and risks. During planning, the team breaks the work into shippable backlog items with clear acceptance criteria and a Definition of Done. Execution focuses on small, testable increments tracked on a project board and coordinated through regular ceremonies such as daily standups, weekly delivery syncs, and sprint demos.

Roles and ownership are explicit: Product Managers define outcomes and prioritize the backlog; Project Managers coordinate delivery, schedules, risks, and communication; Developers implement and test features; QA validates acceptance criteria and quality; and stakeholders provide input and approvals. This clarity of responsibilities helps the team make timely decisions, manage dependencies, and escalate blockers using defined escalation paths.

Quality assurance is embedded throughout the workflow: work is gated by acceptance criteria, CI checks and security scans, unit/integration/end-to-end tests where appropriate, and smoke tests before release. Release practices include pre-release checks, deployment checklists, rollback plans, and post-deploy verification. Retrospectives capture learning and convert action items into backlog tasks to drive continuous improvement.
